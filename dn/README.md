# dn/: DOS Navigator

The file manager itself (DN OSP 2.14 on top of package [`tv/`](../tv/README.md)). **Sources live here, in git**: ordinary
work is ordinary commits and PRs in `dn/src`. Where the first commit came from and how to reproduce it: [`../bootstrap/README.md`](../bootstrap/README.md).
Provenance of each file: [`PROVENANCE.md`](PROVENANCE.md). Licenses: [`LICENSE.md`](LICENSE.md).

## Build with one command

    tools/build.sh linux64        # x86_64 Linux, your fpc 3.2.x; result out/linux64/dn (+ *.LNG *.DLG *.HLP next to it)
    cd out/linux64 && ./dn

Other targets: `linux` (i386, static; needs cross-compiler `tools/build-fpc-i386-linux.sh PREFIX`, `DN_LINUX=PREFIX`),
`dos` (go32v2; `tools/build-fpc-go32v2.sh PREFIX`, `DN_PREFIX=PREFIX`; resources are built by `rcp.exe` in DOSBox-X).
Target options — `build.env`. Tests for our units: `tools/dn-test.sh`.

## What is in the directory

| Path | What |
|---|---|
| `src/` | DN sources (Pascal): program, panels, editor, viewer; resource texts (`RESOURCE/`), `rcpvpd.ini` |
| `archives/` | one unit per archive format (`arc_*.pas`: zip, rar, 7z, tar...) |
| `compat/` | environment DN code expects: Virtual Pascal layer (`osdep`...), Borland units on top of `tv/` (`drivers`, `objutil` (was `baseobjs`)), DPMI32 layer (`realmode`, one unit); `compat/linux/` — unit replacements for non-DOS builds (`country_.pas`) |
| `data/` | data DN reads at runtime (code-page tables, palettes, defaults) |
| `compat/shims/` | description of what DN takes from `tv/` (shim units generated by `tools/gen-shim.py`) |
| `tests/` | tests for our units (`t_*.pas`; `tools/dn-test.sh`) |
| `build.env` | compiler options per target |
| `PROVENANCE.md` | file provenance (generated by `bootstrap/tools/dn-manifest.py`) |
| `LICENSE.md` | which licenses apply to which files |
| `TODO-later.md` | what we are not doing now; doubtful spots |

What lives in which file (map for newcomers): [`FILES.md`](FILES.md).

## Working rules

1. Change `dn/src` with ordinary commits. `bootstrap/` is a record of the first commit; it is not edited in day-to-day work.
2. **Legal gate** (CI, workflow `dn`, job `audit`): no file in `dn/src` may contain verbatim Borland
   code chains (`raw% <= 10` and the longest chain under 48 tokens; `audit/README.md`). Check locally:
   `audit/fetch_reference.sh && python3 audit/xclone.py --min 3 --ref audit/ref/list.txt dn/src`.
   You write the code yourself or take it from DN; not from Turbo Vision, Borland Pascal, Borland docs, or other projects.
3. Do not touch the RIT Labs header in a file. The DN license covers DN code and its derivatives, but not separate files we wrote ourselves that
   link with it into one program (`LICENSE.md`): a new file that does not take code from DN is MIT (`../LICENSE`); after adding a file
   update the manifest: `python3 bootstrap/tools/dn-manifest.py` (CI checks that it is fresh).
4. A file changes under the license in its header (`LICENSE.md`).
5. Doubt or someone else’s bug we noticed — write it in `TODO-later.md`, then back to your task.

## DN license conditions that must be followed

The license in the DN OSP source headers (BSD-like, RIT Research Labs) requires: keep copyright
notices; in binary form reproduce them in documentation; when mentioning the program in advertising, say “Based on Dos Navigator
by RIT Research Labs”; code derived from DN must not be relicensed (including under GPL). These conditions apply to DN files and their derivatives, and to binary builds that contain DN code (that is, all `dn` builds):
notices go in the build documentation (`README.TXT` and `LICENSE-DN.TXT` of every release archive, `tools/dn-notices.sh`). They do not apply to our separate files (MIT).
