# dn/: DOS Navigator

Сам файловый менеджер (DN OSP 2.14 поверх пакета [`tv/`](../tv/README.md)). **Исходники лежат здесь, в git**: обычная
работа — обычные коммиты и PR в `dn/src`. Откуда взялся первый коммит и как это воспроизвести: [`../bootstrap/README.md`](../bootstrap/README.md).
Происхождение каждого файла: [`PROVENANCE.md`](PROVENANCE.md). Лицензии: [`LICENSE.md`](LICENSE.md).

## Собрать одной командой

    tools/build.sh linux64        # x86_64 Linux, ваш fpc 3.2.x; результат out/linux64/dn (+ *.LNG *.DLG *.HLP рядом)
    cd out/linux64 && ./dn

Другие цели: `linux` (i386, статический; нужен кросс-компилятор `tools/build-fpc-i386-linux.sh ПРЕФИКС`, `DN_LINUX=ПРЕФИКС`),
`dos` (go32v2; `tools/build-fpc-go32v2.sh ПРЕФИКС`, `DN_PREFIX=ПРЕФИКС`; ресурсы делает `rcp.exe` в DOSBox-X).
Опции целей — `build.env`. Тесты наших юнитов: `tools/dn-test.sh`.

## Что лежит в каталоге

| Путь | Что |
|---|---|
| `src/` | исходники DN (Pascal), тексты ресурсов (`RESOURCE/`), `rcpvpd.ini` |
| `src-linux/` | юниты, заменяющие юниты `src/` при сборке под Linux (`country_.pas`) |
| `data/` | данные, которые DN читает при работе (таблицы кодовых страниц, палитры, настройки по умолчанию) |
| `shims/` | описание того, что DN берёт из `tv/` (юниты-прокладки генерирует `tools/gen-shim.py`) |
| `tests/` | тесты наших юнитов (`t_*.pas`; `tools/dn-test.sh`) |
| `build.env` | опции компилятора по целям |
| `PROVENANCE.md` | происхождение файлов (генерируется `bootstrap/tools/dn-manifest.py`) |
| `LICENSE.md` | какие лицензии на какие файлы |
| `TODO-later.md` | что не делаем сейчас; сомнительные места |

## Правила работы

1. Меняйте `dn/src` обычными коммитами. `bootstrap/` — запись о первом коммите, его не правят в ежедневной работе.
2. **Юридические ворота** (CI, workflow `dn`, job `audit`): ни в одном файле `dn/src` не должно быть дословных цепочек
   кода Borland (`raw% <= 10` и самая длинная цепочка меньше 48 токенов; `audit/README.md`). Проверить у себя:
   `audit/fetch_reference.sh && python3 audit/xclone.py --min 3 --ref audit/ref/list.txt dn/src`.
   Код вы пишете сами или берёте из DN; из Turbo Vision, Borland Pascal, документации Borland и чужих проектов — нет.
3. Заголовок RIT Labs в файле не трогаем. Лицензия DN держит код DN и его производные, но не отдельные файлы, которые мы написали сами и которые
   линкуются с ним в одну программу (`LICENSE.md`): новый файл, не берущий код из DN, — MIT (`../LICENSE`); после добавления файла
   обновите манифест: `python3 bootstrap/tools/dn-manifest.py` (CI проверяет, что он свежий).
4. Файл меняется под лицензией, которая в его заголовке (`LICENSE.md`).
5. Сомнение или чужая ошибка, которую мы заметили, — запись в `TODO-later.md`, и дальше к своей задаче.

## Условия лицензии DN, которые надо выполнять

Лицензия в заголовке исходников DN OSP (BSD-подобная, RIT Research Labs) требует: сохранять уведомления об авторских
правах; в двоичном виде воспроизводить их в документации; при упоминании программы в рекламе указывать «Based on Dos Navigator
by RIT Research Labs»; код, производный от DN, нельзя перелицензировать (в том числе под GPL). Эти условия действуют для файлов DN и их производных, а также для двоичных сборок, в которых есть код DN (то есть для всех сборок `dn`):
уведомления — в документации сборки (`dist/*/README.TXT`). На наши отдельные файлы (MIT) они не распространяются.
